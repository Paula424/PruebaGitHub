### ¿Que es GitHub?
GitHub es una plataforma para compilar software. Tanto si va a iniciar un nuevo proyecto como si contribuye a uno existente, GitHub reúne las herramientas y los flujos de trabajo que necesita en todas las fases del ciclo de vida de desarrollo de software (SDLC).

![logo de github](https://cdn-icons-png.flaticon.com/256/25/25231.png)

---
### Usos de Github
* Repositorios para organizar tu proyecto. Es la unidad básica de GitHub, ahí vive tu proyecto con su código, documentación, historial y ramas. Cada repo puede ser público o privado, según si quieres compartirlo o mantenerlo solo para tu equipo.
  
* Control de versiones con Git. Cada cambio queda registrado, así puedes volver atrás, comparar versiones y entender la evolución del proyecto. Evita pérdidas de trabajo y permite experimentar sin miedo.
  
* Ramas y fusiones sin romper nada. Trabajas en nuevas funciones o correcciones sin tocar la versión principal, y luego las integras con un merge. Mantienes el producto estable mientras pruebas cosas.
  
* Pull requests para revisar en equipo. Propones cambios, los revisas, comentas líneas concretas y decides si se integran. Convierten la revisión de código en un proceso colaborativo y trazable.
  
* Gestión de tareas dentro del repo. Registras bugs, ideas y tareas en el propio repositorio, con etiquetas, responsables y prioridades. Muy práctico para equipos pequeños y proyectos open source.
  
* Automatización con GitHub Actions. Lanzas tests, despliegues o linting con workflows que se disparan en cada push o pull request. Integras CI/CD sin montar infraestructura adicional.

* Entornos en la nube con Codespaces. Arrancas un entorno de desarrollo listo para usar desde el navegador. Ideal para onboarding o trabajar desde distintos dispositivos sin configurar el proyecto en local.
  
* Wiki y documentación del proyecto. Con los README y la wiki explicas cómo instalar, usar o contribuir. El código con contexto es mucho más fácil de mantener y de colaborar.

### Pasos a seguir para conseguir las diferentes acciones
#### Crear un repositorio
1. Pulsar sobre el botón "New" para crear un nuevo repositorio.
2. Escribir el nombre que queremos darle al repositorio.
3. Seleccionar si queremos que sea público o privado.
4. Opcionalmente, añadir un archivo README.
5. Pulsar en "Create repository".

    Una vez realizados estos pasos, el repositorio estará creado y podremos
    añadir archivos y trabajar con ellos.
---
#### Crear y editar archivos
**Para crear un archivo se deben seguir los siguientes pasos:**
1. Entrar en el repositorio donde queremos crear el archivo.
2. Pulsar sobre "Add file".
3. Seleccionar "Create new file".
4. Escribir el nombre del archivo y su extensión, por ejemplo, README.md.
5. Escribir el contenido del archivo en el editor de GitHub.
6. Escribir un mensaje que describa el cambio realizado.
7. Pulsar en "Commit changes" para guardar los cambios.
---
**Para editar un archivo que ya existe:**
1. Entrar en el repositorio.
2. Seleccionar el archivo que queremos modificar.
3. Pulsar sobre el icono del lápiz o la opción "Edit this file".
4. Realizar los cambios necesarios.
5. Escribir un mensaje indicando qué se ha modificado.
6. Pulsar en "Commit changes".

    De esta forma, GitHub guarda los cambios realizados y permite consultar el historial de modificaciones del archivo.
---
#### Subir un archivo
1. Entrar en el repositorio.
2. Pulsar en "Add file".
3. Seleccionar "Upload files".
4. Arrastrar los archivos al área indicada o seleccionarlos desde el ordenador.
5. Escribir un mensaje para indicar qué cambios hemos realizado.
6. Pulsar en "Commit changes".

   El archivo aparecerá dentro del repositorio.
---
#### Crear una rama
1. Entrar en el repositorio.
2. Pulsar sobre el selector de ramas.
3. Escribir el nombre de la nueva rama.
4. Seleccionar la opción para crear la rama.
5. Realizar los cambios necesarios dentro de esa rama.

    Las ramas permiten trabajar en cambios sin modificar directamente la rama
    principal del proyecto.
---
#### Crear un Pull Request
1. Crear una nueva rama a partir de la rama principal.
2. Realizar los cambios necesarios dentro de esa rama.
3. Guardar los cambios mediante uno o varios commits.
4. Entrar en la sección "Pull requests" del repositorio.
5. Pulsar en "New pull request".
6. Seleccionar la rama que contiene los cambios y la rama a la que queremos incorporarlos.
7. Escribir un título y una descripción explicando los cambios realizados.
8. Pulsar en "Create pull request".
9. Revisar los cambios y, si todo es correcto, se puede aceptar el Pull Request mediante "Merge pull request".

    Los Pull Requests son especialmente útiles cuando varias personas trabajan en un mismo proyecto, ya que permiten revisar los cambios antes de incorporarlos al proyecto principal.
---
#### Crear un Issue
1. Entrar en el repositorio correspondiente.
2. Acceder a la sección "Issues".
3. Pulsar en "New issue".
4. Escribir un título que explique brevemente el problema o tarea.
5. Añadir una descripción detallada de lo que ocurre o de lo que se quiere realizar.
6. Si es necesario, añadir imágenes, archivos u otra información que ayude a explicar el problema.
7. Pulsar en "Submit new issue".
    
   Una vez creado, el Issue puede ser consultado por los miembros del proyecto. También se pueden añadir comentarios, asignar responsables y utilizar etiquetas para organizar los diferentes problemas o tareas.
